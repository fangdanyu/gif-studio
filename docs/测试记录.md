### 双向互认结论（关键）

编解码器与业界标准实现（PIL）**双向兼容**，这是本项目最容易踩坑的地方，实测数据：

- 我们解码 PIL 的产物：3 帧纯色 GIF 逐像素 0 差异；256 色渐变平均通道误差 **2**。
- PIL 解码我们的产物：3 帧纯色 GIF 每帧 3072/3072 像素正确、时长 50/100/200 正确；256 色渐变平均通道误差 **3.07**。

> 早期版本因 LZW 扩位时机（编码端"先扩位后写码"）与标准相差一格，造成"自己解自己没问题、PIL 只能解出一半"的假象。现已按标准时序实现：编码端**先写码、写完后按当前词条数扩位**；解码端在 `next == 1<<codeSize` 时扩位。

## 6. 本轮修复的问题（均有复现与验证）

| 问题 | 现象 | 修复 |
| --- | --- | --- |
| LZW 扩位时机与标准差一格 | 自己解自己正常，PIL 解一半/全黑 | 编码端改为"写码后按词条数扩位"，解码端 `next == 1<<codeSize` 时扩位 |
| 中位切分量化重排数组错位 | 渐变图全黑，平均误差 127 | 重排改为只覆盖当前盒子区间（`working.copyOf()`） |
| BitWriter 直写主输出流 + 缺 minCodeSize 字节 | PIL 报 `image file is truncated` | BitWriter 内部缓冲；`writeLzw` 开头补写 1 字节最小码长 |
| targetSdk 36 强制边到边 | 编辑页「导出」按钮与状态栏电池图标重叠 | 新增 `Ui.applySystemBarInsets()`，四个页面统一补系统栏内边距 |
| 再编辑被降采样到 600 长边 | 324×720 的作品再编辑后变 162×360 | `loadGifProject` 上限提到 1024 |
| 导出档位弹窗首行点击不响应 | 点「高清」无反应（列表首行命中区异常） | 改为自绘可点击行（整行热区），三档均可正常触发 |

### 已知限制（新增）

- 涂鸦笔迹作用于**所有帧**（同一笔画在每帧都出现），没有做"只标注当前帧"的分帧涂鸦；如后续需要可给 `DoodleStroke` 加 frameIndex。
- 体积档的 12 档梯度是经验值：极小目标（如 0.5MB）配大量帧时，可能停在最后一档仍略超目标，此时弹窗会显示真实体积，不会谎报达标。
- 模拟器的 System UI 偶发 ANR 弹窗（模拟器性能问题，与本应用无关），验收时点 Wait 即可继续。

### 多点触控验证方式（需求 1）

adb 的 `input tap/swipe` 只能产生单点事件；本机模拟器以 `-no-window` 启动且为正式版系统镜像（`adbd` 无法 root），向 `/dev/input/event*` 写入触控事件被 SELinux 拒绝，因此无法从宿主机注入双指手势。
为真正验证代码路径，新增 `app/src/androidTest/java/com/gifstudio/editor/PinchGestureTest.kt`，在设备内进程通过 `dispatchTouchEvent` 投递**双指 MotionEvent 序列**（`ACTION_DOWN` → `ACTION_POINTER_DOWN` → `ACTION_MOVE` → `ACTION_POINTER_UP` → `ACTION_UP`），断言图层 `sizeRatio` 与 `rotation` 的变化。执行命令：

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest --console=plain --max-workers=1
# Starting 2 tests on Medium_Phone_API_36.1(AVD) - 16
# Finished 2 tests … BUILD SUCCESSFUL
```

两条用例（`pinchScalesAndRotatesSelectedSticker`、`fixedAspectCropProducesSquareOutput`）均 0 失败。
说明：真机上的双指手势由系统触摸框架正常派发到同一 `onTouchEvent`，本测试覆盖的是应用层全部捏合/旋转逻辑；真机手感（如跟手性）仍需在实机上确认。

### 已知限制（本批新增）

- 图片贴纸的 `Bitmap` 未显式 `recycle()`：数量少、单张限长边 480，占用可控；退出编辑时随项目一起释放。
- 文字旋转后，命中检测用未旋转包围盒近似（包围盒略大于文字实际范围），极端角度下点击空白处也可能选中文字。
- 固定比例裁剪框永远居中生成最大框，切换比例后需重新拖角微调（不保留上一比例的移位）。
- 双指手势在 headless 模拟器上无法用 adb 复现，已用设备内 instrumentation 测试覆盖逻辑；实机手感未经人工验证。
